ADAM — RF & SIGNAL CAPTURE

OBJECTIVE
----------------------------------------------------------------
Set up the development environment and establish the foundation
for RF signal capture using a CC1101 transceiver wired to an
ESP32 via SPI.

CONCEPTS LEARNED
----------------------------------------------------------------
SPI Protocol
  - SPI is a hardware protocol built into the ESP32
  - Master/Slave model — ESP32 is master, CC1101 is slave
  - Four wires:
      SCK   ── clock, controlled by master, syncs both chips
      MOSI  ── ESP32 → CC1101, sends commands and config
      MISO  ── CC1101 → ESP32, sends data back
      CSN   ── chip select, active LOW, taps correct device
  - Full duplex — both sides transmit simultaneously
  - CSN is just a regular GPIO, not special hardware
  - Multiple SPI devices share SCK, MOSI, MISO
    but each gets its own dedicated CSN pin

GDO Pins
  - GDO0 and GDO2 are General Digital Output pins on CC1101
  - Not part of SPI — separate signal pins
  - GDO0 goes HIGH when CC1101 has captured RF data
  - Acts as a trigger — ESP32 watches it, fetches data via SPI
  - GDO2 not needed at this stage, left unconnected
  - Full receive flow:
      1. RF signal arrives at CC1101 antenna wirelessly
      2. CC1101 captures it, stores in internal buffer
      3. CC1101 pulls GDO0 HIGH
      4. ESP32 sees GDO0 HIGH
      5. ESP32 initiates SPI conversation
      6. CC1101 sends data back over MISO
      7. ESP32 prints to Serial monitor

Why CC1101 needs SPI vs simple sensors
  - Simple sensors (ultrasonic, temperature) return one value
    over a single digital or analog pin — no protocol needed
  - CC1101 is a complex programmable chip with ~50 registers
    controlling frequency, modulation, data rate, mode, etc.
  - SPI provides the two-way communication channel needed
    to configure and control the chip AND transfer data back
  - Configuration communication is what makes SPI necessary

ESP32 Pin Knowledge
  - GPIO 6-11   ── internal flash, never use
  - GPIO 0, 12  ── boot sensitive, avoid
  - GPIO 34-39  ── input only, no output
  - Most GPIOs are flexible — digital, analog, SPI, I2C, PWM
  - ADC pins can do analog AND digital — not analog only
  - Hardware SPI (VSPI) defaults: SCK=18, MISO=19, MOSI=23

Board Identified
  - Wemos D1 R32 with ESP32-WROOM-32 module
  - Has dedicated SPI header: SCK(IO18) MISO(IO19) MOSI(IO23)
  - WARNING: SD2/SD3/CMD/CLK/SDO/SD1 row = internal flash,
    never use this row despite being labeled SPI
  - IO2 and IO4 appear in analog section but are digital capable
  - IO15, IO33, IO32 are solder pads — not breadboard friendly

HAZEM — DISPLAY & UI
================================================================

OBJECTIVE
----------------------------------------------------------------
Set up the development environment and establish the foundation
for the display layer using a 1.8" SPI TFT wired to an ESP32,
culminating in a Hello World render on screen.

CONCEPTS LEARNED
----------------------------------------------------------------
SPI Protocol (Display Side)
  - SPI is the communication protocol between ESP32 and display
  - Master/Slave model — ESP32 is master, display is slave
  - Wires used:
      SCK   ── clock, syncs communication
      MOSI  ── ESP32 → display, sends pixel data
      CS    ── chip select, tells display to listen
      DC    ── data/command, tells display type of incoming data
      RST   ── reset, reboots the display controller
  - MISO not needed — display is write only, never talks back
  - DC and RST are extra control pins specific to TFT displays,
    not standard SPI signals

Why IO2 Is Risky
  - IO2 is a strapping pin on ESP32
  - Affects boot behavior — can cause unpredictable issues
  - Safe alternatives: IO27, IO26, IO25, IO32
  - IO27 chosen as replacement for DC pin

Power — BL Pin
  - BL = backlight LED, needs 3.3V not GND
  - Screen will be completely dark if BL is grounded
  - VCC and BL both need 3.3V — bridge both into same
    breadboard power rail row

CS Pin Importance
  - Without CS connected the display won't respond on SPI bus
  - Easy to miss since basic sensor modules often skip CS
  - Display CS wired to IO5

Common Ground Note
  - Adam discovered this during his session — critical rule:
    every component must share a common GND reference
  - External supply GND must be bridged to ESP32 GND pin
  - Will apply this when CC1101 is added to the circuit
